# 精酿酒吧空桶回收押金与批次追溯平台

酒厂向多城市合作酒吧配送 IPA / 世涛 / 小麦 / 酸啤时，围绕**一只桶（keg cycle）**与**一批酒（batch）**
把酒厂仓库、酒吧店长、司机、清洗厂、品控、财务放在同一条链路上协同：

- **发货建档**：桶编号、容量、酒液批次、灌装日期、最佳饮用期、押金金额、配送司机、酒吧收货人、押金账期。
- **开桶反馈**：出酒速度、气压问题、口味异常、客诉；同批次被多家酒吧投诉时品控看板自动给出停售建议。
- **空桶回收**：酒吧打空后按账期预约回收、**店长确认回收时间**；司机逐桶扫码，确认空桶数量、外观、残液、封盖状态；系统审计**司机漏扫**、爽约与**延迟归还**。
- **空桶逾期押金冻结**：超过约定账期未归还时，平台**按桶编号冻结押金**并提醒店长预约回收；
  司机**已到店但酒吧未备好空桶**、酒吧已备货但**司机到店失败**分别登记到场记录，影响逾期责任判定；
  冻结后店长可**上传"已打空但未回收"现场照片**申诉。财务结合照片与到场记录判定责任：
  **酒吧责任**维持冻结可扣款，**司机责任/无责**解除冻结且**押金释放时间按确认回收时间重新计算**。
- **清洗检测**：清洗厂登记耐压/密封/清洁结果；合格桶回库恢复**再灌装资格**，不合格桶冻结并联动财务扣款。
- **押金结算**：财务按桶释放、部分扣款或全额扣款（丢失/变形/清洗不合格/逾期），金额与原因全部留痕。
- **批次停售 / 召回**：一键暂停或召回，自动通知**已收货酒吧（区分已开/未开桶）、待配送订单、经销商库存**并全渠道广播；
  含停售批次的订单发货时强制拦截；召回视图按"未开桶 / 已开桶 / 回收在途 / 已闭环 / 酒厂库存"分层。
- **多城市经销商、押金账期、节日临时铺货**全部支持。

技术栈：**React 18 + Vite（前端） · Go 1.19 net/http（后端） · PostgreSQL 15（数据库）**。
前端构建产物被 Go `embed` 进单个二进制，一个进程同时提供 API 与页面。

## 本地启动

### 方式一：Docker Compose 一键启动（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8080 ；首次启动应用容器会在空库上自动建表并加载种子数据
```

Compose 启动两个服务：`db`（postgres:15，宿主映射端口 **5433**）与 `app`（:8080，
通过 `KEG_DSN=host=db ...` 连库，健康检查通过后才启动）。数据保存在命名卷 `kegpgdata`，
重置演示数据：`docker compose down -v && docker compose up --build`。

### 方式二：本地脚本启动

#### 前置要求

- Go ≥ 1.19
- Node.js ≥ 18（仅前端开发/重新构建时需要）
- PostgreSQL 服务端工具（`initdb`/`pg_ctl`，Debian: `apt install postgresql`）

#### 一键启动

```bash
bash scripts/dev-up.sh
# 想恢复干净演示数据：RESET_DB=1 bash scripts/dev-up.sh
```

脚本会在项目下 `.pgdata/` 初始化一个**用户级 PostgreSQL（端口 5433，trust 认证）**，
创建 `kegplatform` 数据库、加载结构与种子数据，然后启动服务。

打开 <http://localhost:8080> 即可使用。

#### 手动启动

```bash
# 1. PostgreSQL（若系统已有 5433 实例可跳过，用 KEG_DSN 指向自己的库）
export PATH=/usr/lib/postgresql/15/bin:$PATH
initdb -D .pgdata -U node --auth=trust --encoding=UTF8
echo "port = 5433
unix_socket_directories = '/tmp'" >> .pgdata/postgresql.conf
pg_ctl -D .pgdata -l .pgdata/server.log start
createdb -h /tmp -p 5433 -U node kegplatform

# 2. 后端 + 数据初始化
cd backend
go run . init          # 加载 db/schema.sql 与 db/seed.sql
go run .               # http://localhost:8080
# 容器/CI 下可用 go run . auto：库为空时自动初始化再启动

# 3.（可选）前端开发热更新
cd frontend
npm install --cache ../.npm-cache
npm run dev            # http://localhost:5173 ，/api 代理到 8080
# 重新打包进 Go：npm run build（产物输出到 backend/web/dist，然后重新 go run）
```

可用环境变量：`KEG_DSN`（默认 `host=/tmp port=5433 user=node dbname=kegplatform sslmode=disable`）、
`KEG_ADDR`（默认 `:8080`）、`KEG_TOKEN_SECRET`。

## 种子数据里预置的场景（可直接演示）

- **多店口味投诉同一批次**：世涛 `BT2026-ST-01` 被泡沫实验室、醉猫酒馆两家反馈口味异常 → 品控看板建议停售。
- **批次已暂停销售**：酸啤 `BT2026-SOUR-01` 已生成酒吧/待配送订单（节日铺货单 ORD-0910）/经销商/全渠道四类通知。
- **账期逾期**：醉猫酒馆 7 天账期订单已逾期；执行"回收审计"会批量标记延迟归还；财务可一键"按桶编号冻结全部逾期桶押金"。
- **逾期冻结 + 双类到场责任（本次新增）**：
  - `KEG-0016`（cycle 916）已打空未回收，押金 **FROZEN**，店长已上传"已打空"现场照片，收到催还提醒待预约。
  - `KEG-0017`（cycle 917）已冻结，预约 806 有 **司机到店失败（DRIVER_FAILED）** 记录 → 店长确认回收时间后，财务判司机责任即解冻并把释放日重算为「回收日 +7 天」。
  - `KEG-0005`（cycle 905）预约 805 有 **司机已到店·酒吧未备好空桶（BAR_NOT_READY）** 记录 → 判酒吧责任后押金维持冻结，可继续扣款。
- **酒桶丢失**：`KEG-0013` 丢失，押金 ¥500 已全额扣除。
- **桶体变形 + 清洗不合格**：`KEG-0011` 变形、明显残液、封盖损坏，清洗厂判不合格，部分扣款 ¥150、取消再灌装资格。
- **司机漏扫**：预约 802 应收 2 只，只扫了 `KEG-0014`，`KEG-0015` 无扫码记录；点"执行回收审计"自动标出。
- **节日临时铺货**：成都春熙小馆 ORD-0910（双节铺货，15 天账期）含停售酸啤 2 只，发货会被拦截。
- **正常闭环**：`KEG-0012`、`KEG-0014` 已回收、清洗合格、押金释放、桶回库可二次灌装。

### 建议体验路径

1. `qc` 登录 → 品控看板看到世涛"2 家酒吧投诉建议停售" → 进入批次页对 `BT2026-ST-01` 发起暂停，观察通知计数。
2. `bar2` 登录 → 通知中心收到停售通知；在店桶列表看到酸啤桶"批次已停售·停止售卖"红色标记。
3. `bar1` → 对未开桶提反馈（自动开桶）→ 标记打空 → 预约回收。
4. `driver1` → 对预约逐桶扫码（可选择"变形/明显残液/封盖损坏"）；遇到酒吧没备好空桶时点"已到店但酒吧未备好空桶"登记到场 → 点"执行回收审计"看到漏扫 `KEG-0015`。
5. `wash1` → 登记检测，不合格桶被冻结、取消再灌装资格。
6. `finance` → 逾期筛选 → **按桶编号冻结全部逾期桶** → 在冻结行点"查看凭证"核对现场照片与到场记录 →
   对 `KEG-0005` 判**酒吧责任**（维持冻结可扣款）、对 `KEG-0017` 判**司机责任**（解冻，释放日按确认回收时间重算）→ 再做释放/扣款，到"酒桶追溯"看完整时间线。
7. `bar2`（醉猫酒馆）→ 首页看到冻结催还提醒 → 对 `KEG-0016` 上传"已打空未回收"照片、确认回收时间，并能看到责任判定结论提醒。

## 自动化测试与验证方式

```bash
createdb -h /tmp -p 5433 -U node kegplatform_test   # 只需一次
cd backend && go test ./... -v
```

集成测试（`backend/api_test.go`，每个用例独立重建 schema+种子）覆盖：

错误密码/无 token/角色越权/跨店操作被拒；开桶反馈→打空→预约回收；司机扫码与重复扫码拦截；
回收审计发现漏扫与逾期；清洗合格回库/不合格冻结；押金释放/部分扣款/全额扣款/重复结算拦截；
批次暂停自动生成三类定向通知且按角色可见性正确；召回库存分层计数；含停售批次订单发货拦截；
建单→发货正向闭环；按桶事件时间线完整；多店口味投诉触发停售建议；新桶编号连续。

**逾期押金冻结全链路（`TestOverdueFreezeFlow`）**：按桶编号批量冻结且幂等、催还桶级提醒按店隔离；
店长上传已打空现场照片（跨店/非图片被拒）、财务查看照片+到场凭证；冻结未定则禁止结算；
酒吧未备货责任维持冻结后部分扣款；店长确认回收时间（改约/跨店拒绝）、司机到店失败责任解冻且
释放日按「确认回收日+7 天」重算；两类到场记录的角色权限；追溯时间线包含冻结/照片/到场/定责事件。
